# Local storage review and maintenance

MCP latest-value queries read `AppModel.metrics`; they do not read the telemetry journal. Historical watch queries and CSV exports use `HealthHistoryReader`, which consumes watch-origin rows. Cloud chart and HRV caches are separate and account scoped.

The old journal wrote every origin even though cloud/estimated rows were ignored by its consumers. The writer now records finite watch readings only, with kind, timestamp, value and origin; per-row random IDs and repeated source labels are omitted. Existing journal files remain readable. Latest-value updates still happen before journal persistence.

Sync records → Local data → Review Storage offers FIT cleanup, safe log compaction and a separate full-history clear:

- FIT cleanup requires a matching final accepted/duplicate HTTP receipt for the file, a verified content identity and the current account/region. Pending, processing, failed, empty, missing-receipt and other-account references protect shared copies. Ledger and device receipt metadata stay in place for deduplication; no cloud or watch deletion occurs.
- Older journal compaction removes recognized cloud/estimated polling copies and exact repeated watch kind/timestamp/value records. Different timestamps are retained even when values are equal. Unknown lines remain verbatim. Today's active journal is excluded. Watch history curves are unchanged; CSV can lose exact duplicate rows. The log option is unchecked by default.

Inspection runs locally in a utility task and shows file counts and byte estimates before confirmation. Execution revalidates the ledger and file digests, blocks queue mutation while active, prepares journal outputs, and moves originals to a private recovery tree before sending that tree to Trash. On failure it rolls back; an interrupted process leaves originals in a recovery folder under the app's data directory. Relative paths are recorded for restoration. Trash is recoverable, so disk space is only reclaimed after the user empties it.

Tests cover receipt mismatches, cross-account/shared-file protection, changed files and ledgers, symlinks, rollback, active-day protection, historical-series equivalence, duplicate timestamps and compact watch-only writes. Native previews use synthetic data. No real user cleanup is performed during development verification.

Full history clearing is a separate destructive action with a native confirmation. It includes today's telemetry, indexes and all account-scoped chart caches. The journal's serial queue flushes pending writes before an exclusive mutation; failed pending writes abort clearing. Chart writes share a maintenance lock and generation check, rejecting scheduled pre-clear saves. In-flight history/network results are invalidated; in-memory series and recent history reset while current metrics stay. New readings resume and cloud charts reload on demand for available dates. Cloud chart availability does not guarantee recovery of individual watch readings. Both folders move to a private recovery tree and Trash with rollback on failure. FIT, credentials and upload receipts are outside this operation.

Review follow-up: failed clearing retains the original in-memory history, per-day revision counters and unsaved retry collections. State resets and chart-store replacement commit only after the disk operation succeeds. Save callbacks also check the UI history generation, so pre-clear tasks cannot remove retained retry payloads. The native harness creates a genuine chart-write failure, injects failed cleanup, then repairs the fixture path and verifies that retry saves the retained data. The sheet groups FIT cleanup and old-log compaction under selected copies, with a separate all-readings action and a persistent Trash/disk-space hint. Empty, failure and completion previews cover both languages, appearances and text scales.
