# WristBeam component review — 2026-10-27

## Scope and acceptance

The user requested another pass over every button and component after the integrated-settings beta. Settings stay in the main window. This is an explicit product choice; macOS's conventional separate Settings window is not being reinstated.

Baseline: `30ce849`, installed public `v0.3.11-beta.3`. The baseline search found 327 control references; excluding one `NSButton` return-type signature leaves 326 control construction sites across 21 SwiftUI files. A construction site can generate many controls through `ForEach`; this is not a claim that 326 runtime states were exercised. [Per-site catalog](2026-10-27-controls.csv) preserves baseline source locations, code, control-type decisions and page-specific review decisions. AppKit window chrome and application menus are reviewed separately. No private account, watch, location, health values, or FIT data belong in this record or the fixtures.

## Review decisions before implementation

Noninteractive/shared structures also reviewed: `PreferenceBlock`/`PreferenceLine`/`PreferenceRowLayout` (consistent margins, semantic names and leading stacked controls), `PulseCard`/`ConnectIQSurface` (surface/separator contrast and18-point corner family), `PulseNotice`/`PulseEmptyState` (local feedback, no color-only meaning), `StatusDot`/`WatchBatteryBadge` (text accompanies state; timestamp remains available), `MetricCard` (one whole-card action with combined value/origin/time), `MetricIcon` (decorative when a name is already present), `SyncProgressView` (receive/local/cloud are distinct and combine accessible text), `ScrollPositionKeeper` (route-specific positions), `NavigationWindowPolicy` (sheets retain command ownership) and `WebScrollAppearance` (official editor scroll appearance).

AppKit review: actual native close/minimize/zoom buttons, full-screen capability, retained main-window instance, Command-W/M and Control-Command-F, Window-menu reopen Command-0, App/Edit/Go menus, modal navigation guards, file save/open panels, WebKit alert/confirmation/text-input sheets and the system share picker. Localize the login WebKit alert/confirm buttons too; those AppKit controls live outside the SwiftUI catalog. Sheet dismissal stays distinct from quitting the background application. The preview screenshot shortcut now matches Command-S exactly, so it cannot swallow additional-modifier shortcuts.

Window activation was another concrete issue: production stayed in `accessory` policy even while showing its main window. Apple documents that this mode has no application menu bar. `presentMainWindow` now activates regular application mode, and closing the retained window returns to accessory mode so background/menu-bar work continues. CI exercises these transitions. This fixes the standard-menu behavior; it does not establish that activation policy alone caused the missing traffic-light screenshot. [Apple activation-policy documentation](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/accessory).

The first artifact review also caught inconsistent unscaled share-selection labels and default sheet dismissal styling. Standalone sheets/popovers explicitly inherit the shared font, control size and action style now, and dashboard connection actions have padding inside their actual hit targets. Login actions wrap; copying its configuration link reports success/failure; the secure callback field is named and cannot submit empty input. Official vendor form content remains untouched.

Fixed brand-color pairs were calculated from the source sRGB values using WCAG relative luminance: light accent on white / white on light accent6.27:1; dark accent on dark surface12.10:1; black on dark accent15.26:1. These figures do not establish every rendered semantic/disabled/hover color's contrast. System semantic colors retain macOS appearance and accessibility adaptation.

Destructive action text uses a separately measured adaptive red rather than the default bright red:6.76:1 on the light surface and7.28:1 on the dark surface. Back actions use quiet row styling with a32-point minimum instead of a large filled action. Account refresh now shows busy state and prevents repeated requests from the same visible button; sign-out remains available and the controller's authentication-generation guard still prevents an old refresh from restoring a signed-out session.

## Verification record

Local checks are static only: localization coverage, Python syntax, repository policy and diff whitespace. Native build, executable tests and rendering run exclusively in GitHub Actions. CI images use isolated synthetic data. The additional native fixture verifies real standard buttons, normal-window zoom/minimize/close/reopen, regular/accessory transitions, actual full-screen enter/exit callbacks and captures the AppKit frame. Native geometry assertions require the app brand and settings page title to remain inside the viewport; failures preserve all images for review. Window-management fixtures use separate models so their resizing does not alter page-preview scroll state.
