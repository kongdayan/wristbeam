# macOS design beta delivery — 2026-10-28

The requested macOS HIG changes were delivered as the public prerelease [v0.3.11-beta.5](https://github.com/kongdayan/wristbeam/releases/tag/v0.3.11-beta.5), source commit `79c6d4b7f9fe307a5e7311e226c4065248e76d12`, numeric version 0.3.11, build 22. Stable Latest remained v0.3.10. No main merge was part of this beta delivery.

The release includes a permanent Settings entry in the native sidebar, page-specific window titles, system-accent sidebar selection, and a 760 × 600 compact window layout. The native synthetic render matrix checks Chinese and English, light and dark appearances, large text, empty states, settings categories, and window behavior. The macOS 14 compact-window and 160% text captures were reviewed after the successful run.

The first tag, `v0.3.11-beta.4`, stopped at a macOS 14 fixture assertion comparing AppKit's reported minimum window size for exact equality. It was not published or installed. The fixture was changed to check the effective compact window frame and native screenshot; beta 5 passed that check. The first beta 5 workflow attempt then had a macOS 14 runner abandoned while queued. Retrying failed jobs on the same tag and source commit completed [Release run 40668937378](https://github.com/kongdayan/wristbeam/actions/runs/40668937378) successfully: four native build/test targets, quality, CodeQL, artifact provenance, universal packaging, and public asset publication passed.

All five public assets were downloaded and matched GitHub's reported sizes and SHA-256 digests. The three ZIPs matched `SHA256SUMS.txt`; the release manifest matched the source commit and beta tag; package identity, architecture, minimum macOS version, and signatures passed. The arm64 ZIP's GitHub provenance attestation verified.

The verified public arm64 application replaced `/Applications/WristBeam.app`. The prior beta 3 application was moved to Trash after a private local backup of the application, data, and preferences. Data and preferences were byte-identical immediately after replacement, and all original FIT files remained byte-identical after launch. The installed bundle reports beta 5/build 22, its signature validates, and a process from that exact installed path reports a visible Health Dashboard window and retained account session. A separate development instance was left untouched.

Computer-use window capture returned `cgWindowNotFound` for this menu bar application, so no visual claim is based on the installed window. Visual acceptance is based on the CI-rendered native screenshots; runtime verification covers the installed process, bundle, window state, and preserved data. This closing record changes documentation only; the published tag and application code remain unchanged.
